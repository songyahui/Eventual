\begin{abstract}
We present \emph{Pledge}, a Haskell library that extends the classical
pre/post-condition contract model with \emph{future conditions}: specifications
that constrain what the remainder of a program must eventually do.
Future conditions are carried as a \emph{data-dependent} field
\lstinline{future :: a -> eff} in the \lstinline{Pledge} monad
alongside pre- and post-conditions, so that a single operation can
impose obligations that refer to the resource handle it returns.
When operations are composed via monadic bind, future conditions are
evaluated at the current return value, propagated and updated
automatically using a subtraction operator, and preconditions
accumulate in the Hoare-rule style.
The design is parameterised over a \lstinline{Composable} algebra, admitting
four distinct instances.
In the \emph{regular-expression} instance ($\RE$), future conditions are
extended REs with complement---whose derivative commutes algebraically with
negation, avoiding automaton construction---and subtraction is the Brzozowski
quotient.
In the \emph{guarded regular-expression} instance ($\GRE$), a Presburger
arithmetic predicate over the heap is conjoined with a trace RE, enabling
arithmetic bounds (e.g.\ counter overflow) to be enforced alongside protocol
ordering.
In the \emph{weighted regular-expression} instance ($\WRE$), a semiring weight
is attached to RE transitions, unifying probabilistic obligations (probability
semiring) and min-cost scheduling (tropical semiring) in a single framework.
In the \emph{separation-logic} instance ($\SL$), future conditions are heap
predicates with separating conjunction ($*$), ordinary conjunction ($\wedge$),
magic wand ($-*$), and Presburger arithmetic pure constraints;
subtraction is the magic wand.
All four instances reuse the same monadic bind formula, demonstrating that
the framework captures trace-based, arithmetic, quantitative, and
heap-ownership obligations within a single algebraic interface.
\end{abstract}

\keywords{temporal specification, monadic effects, regular expressions,
          complement, Brzozowski derivatives, Presburger arithmetic,
          semiring weights, separation logic, resource lifecycle, Haskell}

\section{Introduction}
\label{sec:intro}
%% =========================================================================

Pre- and post-conditions are the workhorse of modular program specification.
A pre-condition constrains the state in which an operation may be called;
a post-condition describes what holds once it returns. Together they reason
about a single \emph{call boundary}. Yet many correctness properties span
multiple calls separated by unbounded intervening computation:

\begin{itemize}
  \item Every \lstinline{malloc(a)} must eventually be followed by
        \lstinline{free(a)}, and \lstinline{free(a)} must not be called twice
        without an intervening \lstinline{malloc(a)}.
  \item Every \lstinline{open(f)} must eventually be followed by
        \lstinline{close(f)}.
  \item Every \lstinline{beginTx} must eventually reach
        \lstinline{commit} or \lstinline{rollback}.
  \item Every \lstinline{acquire(m)} must eventually be followed by
        \lstinline{release(m)}.
\end{itemize}

These are \emph{deferred obligations}---temporal constraints on what the
\emph{rest} of the program must do after an operation is invoked.
Pre/post reasoning cannot express them: a post-condition records what is
true \emph{now}, not what must become true \emph{later}.

We propose \emph{pledges} as a lightweight, compositional
mechanism for specifying such obligations.
A pledge is a regular expression over events that the remaining
execution trace must match.
It is carried as a third annotation---alongside \lstinline{pre} and
\lstinline{post}---in an \lstinline{Effectful} monad.

Four design elements distinguish Pledge from prior work.
First, the regular-expression language is extended with a
\emph{complement} operator $\neg r$, letting us write the universal
language as $\univ\;(=\neg\varnothing)$ and globally-always assertions
as $\neg(\univ\cdot\neg\phi)$, all without building automata:
the derivative of $\neg r$ is $\neg(\partial_a r)$, so the whole
apparatus is purely algebraic.
Second, the $\GRE$ instance pairs each RE with a Presburger arithmetic
predicate over the heap, checked by an SMT solver, so a single
annotation covers both protocol ordering and arithmetic safety.
Third, the $\WRE$ instance replaces Boolean membership with a semiring
weight, enabling probabilistic and min-cost future conditions without
changing the bind formula.
Fourth, the \lstinline{pre} field is propagated in the
\emph{Hoare-rule} style: the precondition of a sequenced computation
is the precondition of the first step, plus the residual of the
continuation's precondition not discharged by the first step's
postcondition.

\paragraph{Contributions.}
\begin{enumerate}
  \item We define the \lstinline{Effectful} monad (\S\ref{sec:effectful}),
        parameterised over a \lstinline{Composable} algebra, with
        \lstinline{pre}, \lstinline{post}, and \lstinline{future :: a -> eff}
        fields.  The \lstinline{future} field is \emph{data-dependent}: it is
        a function of the return value, so obligations can refer to the
        resource handle an operation produces.  We verify that the monad laws
        hold for the $(\ret, \post, \fut)$ triple (\S\ref{sec:monad-laws}).
  \item We instantiate the algebra to extended regular expressions over
        events with complement, using Brzozowski derivatives to implement
        subtraction---the core of future-condition propagation
        (\S\ref{sec:re})---and show that LTL\textsubscript{f} operators
        embed directly as RE terms (\S\ref{sec:ltl}).
  \item We extend the RE instance to a \emph{guarded} form ($\GRE$,
        \S\ref{sec:guardedre-instance}), pairing each RE with a Presburger
        arithmetic predicate over a concrete heap.  The predicate is
        evaluated by an SMT solver (Z3 via SBV) at membership-check time,
        enabling arithmetic range constraints to be enforced alongside
        protocol ordering in the same \lstinline{Composable} framework.
  \item We provide a \emph{weighted} RE instance ($\WRE$,
        \S\ref{sec:wre-instance}), parameterised over a semiring, that
        generalises Boolean membership to a quantitative weight.  The
        probability semiring recovers probabilistic future conditions;
        the tropical semiring gives min-cost obligations.
  \item We provide a fourth, independent instantiation to separation-logic
        heap predicates (\S\ref{sec:sl-instance}), where separating
        conjunction plays the role of sequential composition, magic wand
        plays the role of subtraction, and Presburger arithmetic provides
        pure constraints. This demonstrates the generality of the
        \lstinline{Composable} interface beyond trace-based specifications.
  \item We demonstrate the approach on ten use cases across all four instances
        (\S\ref{sec:examples}), showing that resource leaks, ordering
        violations, arithmetic overflows, probabilistic obligations, and
        heap-ownership errors all surface as non-trivial residual annotations.
\end{enumerate}

\subsection{Extended Regular Expressions over Events}
\label{sec:re}

Events carry a name and typed arguments.

\begin{lstlisting}
data Term  = Var String | Str String | Num Int
data Event = Atom String [Term]   -- concrete event, e.g. Atom "send" [Num 1]
           | Wildcard             -- pattern matching any single event
\end{lstlisting}

The specification language is an \emph{extended} regular expression type
that adds complement as a first-class constructor:

\[
  r \;::=\; \varnothing \mid \varepsilon \mid e \mid r_1 \cdot r_2
          \mid r_1 \vee r_2 \mid r_1 \wedge r_2 \mid r^* \mid \neg r
\]

Here $e$ is a \lstinline{Single Event} that uses \lstinline{Wildcard} as a
pattern for any event, $\wedge$ is intersection (derived:
$r_1\wedge r_2 \triangleq \neg(\neg r_1\vee\neg r_2)$), and
$\neg r$ is the complement with respect to $\Sigma^*$.

\begin{lstlisting}
data RE = Bot | Epsilon | Single Event
        | Seq RE RE | Or RE RE | And RE RE | Star RE | Not RE
\end{lstlisting}

Five derived forms are used throughout:

\begin{align*}
  \anything &\;\triangleq\; \neg\varnothing
            &&\text{(the universal language } \Sigma^*\text{)} \\
  \finally{e} &\;\triangleq\; \anything \cdot e \cdot \anything
            &&\text{($e$ must occur eventually)} \\
  \mathtt{globally}(e) &\;\triangleq\; e^*
            &&\text{($e$ at every step)} \\
  \mathtt{never}(e) &\;\triangleq\; \neg\finally{e}
            &&\text{($e$ must never occur)} \\
  \mathtt{noUntil}(e,\,g) &\;\triangleq\;
            \neg\bigl((\Sigma\setminus\{g\})^* \cdot e \cdot \anything\bigr)
            &&\text{($e$ must not occur before $g$)}
\end{align*}

\noindent
$\mathtt{noUntil}(e,\,g)$ is nullable (the empty continuation satisfies it)
and its derivative with respect to $g$ is $\Sigma^*$, meaning once $g$ occurs
the restriction on $e$ is lifted.
This is the key combinator for \emph{conditional} safety: $e$ is forbidden
until $g$ re-enables it.

\subsection{Algebraic Complement and Brzozowski Derivatives}
\label{sec:deriv}

The Brzozowski derivative~\cite{brzozowski1964} $\partial_a(r)$
computes the language of continuations after reading event $a$.
The key law for complement is:

\begin{equation}
  \partial_a(\neg r) \;=\; \neg\bigl(\partial_a(r)\bigr)
  \label{eq:deriv-not}
\end{equation}

The nullability function $\nu(r)$ ($= \mathtt{True}$ iff
$\varepsilon \in L(r)$) satisfies $\nu(\neg r) = \neg\,\nu(r)$.
Together, equations~\eqref{eq:deriv-not} and the De Morgan laws

\[
  \neg(r_1\vee r_2) = \neg r_1\wedge\neg r_2
  \qquad
  \neg(r_1\wedge r_2) = \neg r_1\vee\neg r_2
\]

allow complement to be propagated and simplified \emph{purely
algebraically}, without building a DFA.
The normaliser additionally applies $\neg\neg r = r$,
$\neg\varnothing = \univ$, and $\neg\univ = \varnothing$.

In Haskell:

\begin{lstlisting}
nullable :: RE -> Bool
nullable (Not r)     = not (nullable r)      -- nu(Not r) = not(nu(r))
nullable (Star _)    = True
nullable (Seq r1 r2) = nullable r1 && nullable r2
nullable (Or  r1 r2) = nullable r1 || nullable r2
nullable (And r1 r2) = nullable r1 && nullable r2
nullable Epsilon     = True
nullable _           = False

derivative :: Event -> RE -> RE
derivative e (Not r)      = Not (derivative e r)   -- d_a(Not r) = Not(d_a(r))
derivative e (Single p)   = if matchEvent e p then Epsilon else Bot
derivative e (Seq r1 r2)
    | nullable r1 = Or (Seq (derivative e r1) r2) (derivative e r2)
    | otherwise   = Seq (derivative e r1) r2
derivative e (Or  r1 r2)  = Or  (derivative e r1) (derivative e r2)
derivative e (And r1 r2)  = And (derivative e r1) (derivative e r2)
derivative e (Star r)     = Seq (derivative e r) (Star r)
derivative _ _            = Bot
\end{lstlisting}

The \lstinline{firstWith} function returns the set of events---drawn from
a supplied finite alphabet $\Sigma_0$---that can begin a word in $L(r)$,
driving the subtraction algorithm.
The complement case requires care.
Naively writing \lstinline{first (Not r) = first r} is \emph{unsound}:
$L(\neg r)$ can begin with events \emph{not} in $\mathit{first}(r)$,
so the na\"ive rule explores the wrong direction.
The correct characterisation is:

\begin{equation}
  e \in \mathit{first}(\neg r,\,\Sigma_0)
  \;\iff\;
  e \in \Sigma_0
  \;\wedge\;
  \lceil\partial_e(r)\rceil \neq \univ
  \label{eq:first-not}
\end{equation}

That is, $e$ can open a word in $L(\neg r)$ iff after consuming $e$,
the residual $\partial_e(r)$ does \emph{not} cover the whole future---there
exists some continuation that stays outside $L(r)$.
The alphabet $\Sigma_0$ is collected from an RE via \lstinline{atoms},
which recursively gathers all concrete (\lstinline{Atom}) events,
excluding \lstinline{Wildcard}.

\begin{lstlisting}
atoms :: RE -> [Event]
atoms (Single Wildcard) = []
atoms (Single e)        = [e]
atoms (Seq r1 r2)       = atoms r1 `union` atoms r2
atoms (Or  r1 r2)       = atoms r1 `union` atoms r2
atoms (And r1 r2)       = atoms r1 `union` atoms r2
atoms (Star r)          = atoms r
atoms (Not r)           = atoms r
atoms _                 = []

firstWith :: [Event] -> RE -> [Event]
firstWith _    Bot               = []
firstWith _    Epsilon           = []
firstWith _    (Single e)        = [e]
firstWith alph (Seq r1 r2)
    | nullable r1                = firstWith alph r1 `union` firstWith alph r2
    | otherwise                  = firstWith alph r1
firstWith alph (Or  r1 r2)      = firstWith alph r1 `union` firstWith alph r2
firstWith alph (And r1 r2)      = [e | e <- firstWith alph r1,
                                        e `elem` firstWith alph r2]
firstWith alph (Star r)         = firstWith alph r
firstWith alph (Not r)          = [e | e <- alph,
                                        not (isTotal (normalize (derivative e r)))]
  where isTotal (Not Bot) = True; isTotal _ = False
\end{lstlisting}

\noindent
The function \lstinline{first r = firstWith (atoms r) r} is a convenient
wrapper for standalone use; inside \lstinline{subtraction} both operands
contribute to the alphabet (see \S\ref{sec:re-instance}).

\paragraph{Illustrative cases.}
Table~\ref{tab:firstwith-not} gives representative evaluations of
\lstinline{firstWith} with \lstinline{Not}, ordered from simple to
non-trivial.
The first three rows confirm that the complement of a single pattern,
a sequence, or a union does not exclude any alphabet event---every event
can open some word in the complement.
The double-negation row shows that \lstinline{firstWith} correctly restores
the original first set: $\partial_b(\neg a) = \neg\varnothing = \Sigma^*$
is total, so $b$ is filtered out by the $\lceil\cdot\rceil \neq \univ$
check.
The last two rows are the most instructive.
In $\neg(a \cdot \Sigma^*)$ (words not starting with $a$), the derivative
$\partial_a(a \cdot \Sigma^*)$ normalises to $\Sigma^*$---consuming $a$
leaves every future possible---so $a$ is \emph{excluded}; only $b$ survives.
Similarly, $\neg(a\cdot\Sigma^* \vee b\cdot\Sigma^*)$ excludes both $a$
and $b$, leaving only $c$.
The De Morgan row checks that \lstinline{firstWith} handles complement
pushed inside a conjunction: $\neg(\neg a \wedge \neg b) = a \vee b$
(by De Morgan and double negation), and indeed only $a$ and $b$ appear.

\subsection{Embedding LTL\texorpdfstring{\textsubscript{f}}{f}}
\label{sec:ltl}

Because complement is a first-class constructor, the standard
LTL\textsubscript{f} operators translate directly into RE---no
automaton construction is needed.
Table~\ref{tab:ltl} gives the full mapping.

\begin{table}[ht]
\caption{LTL\textsubscript{f} to RE translation.
         $\Sigma^1 \triangleq \mathtt{Single\;Wildcard}$,
         $\univ \triangleq \neg\varnothing$.}
\label{tab:ltl}
\begin{tabular}{ll}
\toprule
LTL formula & RE $\sem{\cdot}$ \\
\midrule
$\top$              & $\univ$ \\
$\bot$              & $\varnothing$ \\
$e$                 & $\{e\}$ \\
$\neg\phi$          & $\neg\sem{\phi}$ \\
$\phi \wedge \psi$  & $\sem{\phi} \cap \sem{\psi}$ \\
$\phi \vee \psi$    & $\sem{\phi} \cup \sem{\psi}$ \\
$X\,\phi$           & $\Sigma^1 \cdot \sem{\phi}$ \\
$F\,\phi$           & $\univ \cdot \sem{\phi}$ \\
$G\,\phi$           & $\neg(\univ \cdot \neg\sem{\phi})$ \\
$\phi\,U\,\psi$     & $\mathit{step}(\phi)^* \cdot \sem{\psi}$
                      \quad ($\phi$ propositional) \\
\bottomrule
\end{tabular}
\end{table}

The complement operator does the heavy lifting.
$\neg\phi$ maps to $\neg\sem{\phi}$ in one step.
$G\,\phi \triangleq \neg F\neg\phi$ unfolds to
$\neg(\univ\cdot\neg\sem{\phi})$---``no suffix violates
$\phi$''---using two applications of $\neg$ and no auxiliary
construction.
$F\,\phi$ and $X\,\phi$ need only concatenation.

The $U$ case is the exception.
$\phi\,U\,\psi$ requires $\phi$ to hold at each individual step
before $\psi$, so the translation uses
$\mathit{step}(\phi)$---the length-1 RE for a single event
satisfying $\phi$.
This is well-defined when $\phi$ is propositional; for temporal
$\phi$ (e.g.\ $X\,\phi'$) there is no valid single-step projection,
and the translation is undefined.

\section{The \texttt{Effectful} Monad}

\subsection{The \texttt{Composable} Class}

We abstract the specification algebra via a type class:

\begin{lstlisting}
class Composable a where
  concatenation :: a -> a -> a   -- (<>), unit: empty
  conjunction   :: a -> a -> a   -- (/\), unit: universe
  empty         :: a             -- identity for <>  (varepsilon)
  universe      :: a             -- identity for /\  (neg-emptyset)
  subtraction   :: a -> a -> a   -- (\\)
\end{lstlisting}

\noindent
The five operations form exactly the interface required by the bind
formula---no more, no less.
\lstinline{concatenation} sequences effects (used for \lstinline{post}
and \lstinline{pre}); \lstinline{conjunction} combines simultaneous
constraints (used for \lstinline{future}); \lstinline{subtraction}
computes the residual obligation (the Brzozowski quotient for the RE
instance).
\lstinline{empty} and \lstinline{universe} are the respective identity
elements and appear in \lstinline{pure}.
The class assumes \lstinline{(<>)} is associative with unit
\lstinline{empty}, and \lstinline{universe} is the unit for
\lstinline{(/\\)}; \lstinline{subtraction} satisfies
$\varepsilon \setminus r = r$ and $\univ \setminus r = \varepsilon$.

Normalization is \emph{not} part of the class.
It is an RE-specific simplification called internally by
\lstinline{subtraction}; a different \lstinline{Composable} instance
need not define it at all.

\subsection{The \texttt{Effectful} Type}
\label{sec:future-cond}

The \lstinline{future} field is \emph{data-dependent}: it is a function of
the return value \lstinline{a}, allowing obligations to refer to the resource
handle an operation produces.
The helper \lstinline{evalFuture} evaluates this function at the
computation's own return value.

\begin{lstlisting}
data Effectful eff a = Effectful
  { ret    :: a
  , pre    :: eff        -- what must have occurred before
  , post   :: eff        -- what this computation produces
  , future :: a -> eff   -- obligation indexed by the return value
  }

evalFuture :: Effectful eff a -> eff
evalFuture e = future e (ret e)
\end{lstlisting}

\subsection{Monad Instances}

\lstinline{pure} introduces a computation with no effect and no obligation:

\begin{lstlisting}
pure x = Effectful
  { ret = x, pre = universe, post = empty, future = \_ -> universe }
\end{lstlisting}

The bind operator sequences two computations.
Let $e_2 = f(\ret(e))$.

\begin{lstlisting}
e >>= f = let fe = f (ret e) in Effectful
  { ret    = ret fe
  , pre    = pre e /\ (post e \\ pre fe)
  , post   = post e <> post fe
  , future = \_ -> (post fe \\ future e (ret e)) /\ future fe (ret fe)
  }
\end{lstlisting}

\paragraph{Future condition.}
Each \lstinline{future} function is applied to the corresponding
\lstinline{ret} before the obligation is propagated:

\begin{equation}
  \fut(e \mathbin{>\!\!>\!\!=} f)
  \;=\;
  \bigl(\post(e_2) \setminus \fut(e)(\ret(e))\bigr)
  \;\wedge\;
  \fut(e_2)(\ret(e_2))
  \label{eq:future-bind}
\end{equation}

removes from $e$'s future obligation (evaluated at $e$'s return value)
those traces that $e_2$'s postcondition satisfies, then intersects the
residual with $e_2$'s own future obligation (evaluated at $e_2$'s return
value).
When the result normalises to $\univ$, all obligations are discharged.

\paragraph{Precondition.}

\begin{equation}
  \pre(e \mathbin{>\!\!>\!\!=} f)
  \;=\;
  \pre(e) \;\wedge\; \bigl(\post(e) \setminus \pre(e_2)\bigr)
  \label{eq:pre-bind}
\end{equation}

The term $\post(e) \setminus \pre(e_2)$ is the \emph{residual
precondition}: the part of $e_2$'s precondition not already discharged
by $e$'s postcondition.
The combination uses $\wedge$ (intersection): both $\pre(e)$ and the
residual must hold \emph{simultaneously} in the same input history.

When $\post(e)$ does not cover $\pre(e_2)$ at all, the residual is
$\varnothing$, and $\pre(e) \wedge \varnothing = \varnothing$,
flagging a precondition violation.

When $\post(e)$ \emph{exactly} satisfies $\pre(e_2)$, the residual is
$\varepsilon$, and the combined precondition becomes
$\pre(e) \wedge \varepsilon$.
The outcome depends on whether $\varepsilon \in L(\pre(e))$:
\begin{itemize}
  \item $\pre(e) = \univ$ (nullable, $\varepsilon \in L(\univ)$):
        $\univ \wedge \varepsilon = \varepsilon$.
        The composed computation requires an empty input history---it
        can be called at the very start, once the internal
        $\post(e) \vdash \pre(e_2)$ handshake is satisfied within the
        composition.
  \item $\pre(e) = \{a\}$ (non-nullable, $\varepsilon \notin L(\{a\})$):
        $\{a\} \wedge \varepsilon = \varnothing$.
        The history cannot simultaneously be ``contains event $a$''
        and ``is empty''; the requirements are contradictory and
        $\pre$ correctly collapses to $\varnothing$.
\end{itemize}

This behaviour is intentional.
The $\wedge$ operator records both constraints faithfully; when they
are incompatible the intersection is empty, immediately flagging the
conflict rather than silently discarding one side.

\subsection{Intuition via an Example}

\lstinline{malloc} returns the allocated address as its return value;
the future condition is data-dependent, referring to whatever address
was actually returned via the lambda parameter \lstinline{r}.
\lstinline{free} asserts that \lstinline{free(a)} must not recur
until \lstinline{malloc(a)} happens first, preventing double-free while
allowing re-allocation.

\begin{lstlisting}
type Addr = Int

malloc :: Addr -> Effectful RE Addr
malloc a = Effectful
  { ret = a, pre = universe
  , post   = Single (Atom "malloc" [Num a])
  , future = \r -> finally (Atom "free" [Num r]) }

free :: Addr -> Effectful RE ()
free a = Effectful
  { ret = ()
  , pre    = previously (Atom "malloc" [Num a])
  , post   = Single (Atom "free" [Num a])
  , future = \_ -> noUntil (Atom "free" [Num a]) (Atom "malloc" [Num a]) }
\end{lstlisting}

\noindent\textbf{Good program: \lstinline{addr <- malloc 1; free addr}.}
After \lstinline{malloc 1} ($\ret = 1$):
\[
  \post = \mathtt{malloc}(1),\quad
  \fut  = \finally{\mathtt{free}(1)},\quad
  \pre  = \univ
\]
Binding \lstinline{free 1} (with $\pre = \mathtt{malloc}(1)$, $\post =
\mathtt{free}(1)$):

\textit{Precondition:}
$\post(\mathtt{malloc}(1)) \setminus \pre(\mathtt{free}(1))
= \mathtt{malloc}(1) \setminus \mathtt{malloc}(1) = \varepsilon$.
So $\pre = \univ \wedge \varepsilon = \varepsilon$.\ \checkmark

\textit{Future:}
$\mathtt{free}(1) \setminus \finally{\mathtt{free}(1)} = \univ$.
Intersect with $\fut(\mathtt{free}(1)) = \noUntil{\mathtt{free}(1)}{\mathtt{malloc}(1)}$:
result $\noUntil{\mathtt{free}(1)}{\mathtt{malloc}(1)}$.\ \checkmark
(nullable: the program may end here; no double-free obligation is pending.)

\noindent\textbf{Bad: \lstinline{free 1} alone.}
\lstinline{pure ()} has $\post = \varepsilon$.
$\mathtt{malloc}(1) \setminus \varepsilon = \varnothing$.
So $\pre = \varnothing$.\ \texttimes

\noindent\textbf{Bad: \lstinline{missingFree} (\lstinline{malloc 1 >> malloc 2 >> free 1}).}
The future of \lstinline{malloc 2} is $\finally{\mathtt{free}(2)}$,
which is not discharged by \lstinline{free 1}, so the residual future
still contains $\finally{\mathtt{free}(2)}$, naming the missing free precisely.

\noindent\textbf{Bad: \lstinline{doubleFreeImmediate} (\lstinline{addr <- malloc 1; free addr; free addr}).}
After the first \lstinline{free 1}, the future is
$\noUntil{\mathtt{free}(1)}{\mathtt{malloc}(1)}$.
The second \lstinline{free 1} posts $\mathtt{free}(1)$; consuming
$\mathtt{free}(1)$ in $\noUntil{\mathtt{free}(1)}{\mathtt{malloc}(1)}$
yields $\varnothing$, so the combined future is $\varnothing$.\ \texttimes

\section{The RE Instance}
\label{sec:re-instance}
%% =========================================================================

The \lstinline{Composable RE} instance maps library operations onto
\lstinline{RE} constructors and implements subtraction via derivatives:

\begin{lstlisting}
instance Composable RE where
  concatenation = Seq
  conjunction   = And
  empty         = Epsilon
  universe      = anything      -- = Not Bot

  subtraction Epsilon   r2 = r2
  subtraction (Not Bot) _  = Epsilon   -- Sigma* \\ r = eps (trivially satisfied)
  subtraction r1 r2 =
    let alph   = atoms r1 `union` atoms r2   -- combined alphabet
        evts   = firstWith alph r1
        step e = subtraction (normalize (derivative e r1))
                              (normalize (derivative e r2))
    in foldr Or Bot (map step evts)

normalize :: RE -> RE   -- RE-specific; not part of Composable
normalize r = {- ... algebraic simplification ... -}
\end{lstlisting}

The third clause handles the universal-precondition case:
$\univ \setminus r = \varepsilon$ for any $r$.
The general clause collects the alphabet from \emph{both} operands
before calling \lstinline{firstWith}: this ensures that an event
appearing only in $r_2$ (e.g.\ a future obligation) is still considered
as a potential first step when $r_1$ contains a complement.
Equation~\eqref{eq:first-not} then checks, for each candidate $e$,
whether $\lceil\partial_e(r_1)\rceil \neq \univ$---confirming that
$e$ can genuinely open a word outside $L(r_1)$---before the
derivative pair is explored.

\lstinline{normalize} sits outside the instance and applies the
following RE-specific laws, exploiting the complement constructor:

\begin{center}
\begin{tabular}{ll}
\toprule
Law & Applied to \\
\midrule
$\varepsilon \cdot r = r$, $r \cdot \varepsilon = r$ & \lstinline{Seq} \\
$\varnothing \vee r = r$, $r \vee \univ = \univ$ & \lstinline{Or} \\
$\varnothing \wedge r = \varnothing$, $r \wedge \univ = r$ & \lstinline{And} \\
$\neg\neg r = r$ & \lstinline{Not} \\
$\neg(r_1\vee r_2) = \neg r_1\wedge\neg r_2$ & \lstinline{Not} \\
$\neg(r_1\wedge r_2) = \neg r_1\vee\neg r_2$ & \lstinline{Not} \\
$\neg\varnothing = \univ$, $\neg\univ = \varnothing$ & \lstinline{Not} \\
$\varnothing^* = \varepsilon$, $\varepsilon^* = \varepsilon$ & \lstinline{Star} \\
\bottomrule
\end{tabular}
\end{center}

%% =========================================================================
\section{The GuardedRE Instance}
\label{sec:guardedre-instance}
%% =========================================================================

The RE instance reasons about event traces but knows nothing about
arithmetic state.
The $\GRE$ instance closes this gap: a guarded regular expression pairs
a trace RE with a Presburger arithmetic predicate over a concrete heap,
so that one annotation can simultaneously enforce a protocol ordering
\emph{and} an arithmetic bound.

\subsection{The \texttt{GuardedRE} Type}

\begin{lstlisting}
data GuardedRE = GuardedRE PPred RE
    deriving (Eq)
\end{lstlisting}

A state $(\text{heap},\text{trace})$ satisfies \lstinline{GuardedRE p r} iff
\[
  \text{heap} \models p \quad\wedge\quad \text{trace} \in L(r).
\]
The two sides are independent: $p$ is a static constraint on the heap,
while $r$ advances through Brzozowski derivatives as events arrive.

Two smart constructors lift a pure RE or a pure Presburger predicate:

\begin{lstlisting}
fromRE    :: RE    -> GuardedRE
fromRE r   = GuardedRE PTrue r        -- no heap constraint

fromPPred :: PPred -> GuardedRE
fromPPred p = GuardedRE p universe    -- accept any trace
\end{lstlisting}

\subsection{The \texttt{Composable GuardedRE} Instance}

\begin{lstlisting}
instance Composable GuardedRE where
    concatenation (GuardedRE p1 r1) (GuardedRE p2 r2) =
        GuardedRE (normalizePPred (PAnd p1 p2)) (normalize (Seq r1 r2))
    conjunction (GuardedRE p1 r1) (GuardedRE p2 r2) =
        GuardedRE (normalizePPred (PAnd p1 p2)) (normalize (And r1 r2))
    empty    = GuardedRE PTrue Epsilon
    universe = GuardedRE PTrue (Not Bot)   -- = anything
    subtraction (GuardedRE p1 r1) (GuardedRE p2 r2) =
        GuardedRE (normalizePPred (PAnd p1 p2))
                  (normalize (reSubtraction r1 r2))
\end{lstlisting}

\noindent
Both \lstinline{concatenation} and \lstinline{subtraction} \emph{conjoin}
both heap predicates: the residual must respect the constraints from
both sides.
The RE component uses the same \lstinline{reSubtraction} and
\lstinline{normalize} as the plain RE instance.

\subsection{Presburger Normalisation}

Composing multiple \lstinline{GuardedRE} values accumulates a tree of
\lstinline{PAnd} nodes.
\lstinline{normalizePPred} flattens this tree, removes duplicates,
substitutes equalities (e.g.\ $h[a]=k \Rightarrow$ replace $\mathtt{ValAt}\;a$
by $k$ everywhere), evaluates literal comparisons, and replaces
$\lnot\mathbf{true}$ with the canonical $\mathbf{false}$ constructor
\lstinline{PFalse}:

\begin{lstlisting}
data PPred
    = PTrue | PFalse      -- canonical true/false
    | PLt PExpr PExpr | ...
    | PNot PPred | PAnd PPred PPred

normalizePPred :: PPred -> PPred
normalizePPred p = rebuildAnd (substEqs eqs atoms)
  where
    atoms = flattenAnd (normStep p)
    eqs   = [ (a, k) | PEq (ValAt a) (Lit k) <- atoms ]
\end{lstlisting}

The introduction of \lstinline{PFalse} prevents the solver from being
invoked with expressions like $(\lnot\mathbf{true}) \wedge \cdots$ that
are syntactically unsatisfiable; instead they normalise immediately to
\lstinline{PFalse}.

\subsection{Membership Checking}

Checking whether a concrete $(heap, trace)$ satisfies a
\lstinline{GuardedRE} involves two steps: fold \lstinline{deriveGuarded}
over the trace (advancing only the RE side), then call
\lstinline{nullableGuarded} which checks RE nullability \emph{and}
invokes the SBV/Z3 backend on the instantiated Presburger predicate.

\begin{lstlisting}
deriveGuarded :: Event -> GuardedRE -> GuardedRE
deriveGuarded e (GuardedRE p r) = GuardedRE p (normalize (derivative e r))

nullableGuarded :: Map Addr Int -> GuardedRE -> IO Bool
nullableGuarded heap (GuardedRE p r)
    | not (nullable r) = return False
    | otherwise = do
        result <- checkPPred (instantiate heap p)
        return $ case result of { Satisfied _ -> True; _ -> False }

checkGuarded :: Map Addr Int -> [Event] -> GuardedRE -> IO Bool
checkGuarded heap trace g =
    nullableGuarded heap (foldl (flip deriveGuarded) g trace)
\end{lstlisting}

\subsection{Example: Bounded Counter}

A bounded counter stored at heap address $a$ with maximum value $M$
must follow the protocol $\mathtt{init}\cdot(\mathtt{inc}\mid\mathtt{dec})^*\cdot\mathtt{snapshot}$.
Increment is additionally guarded by $h[a] < M$ (no overflow); decrement
by $h[a] > 0$ (no underflow).

\begin{lstlisting}
initCounter :: Addr -> Pledge GuardedRE ()
initCounter a = Pledge
  { ret = ()
  , pre  = fromRE universe
  , post = GuardedRE (PEq (ValAt a) (Lit 0))
                     (Single (Atom "init" [Num a]))
  , future = \_ -> fromRE universe }

increment :: Addr -> Int -> Pledge GuardedRE ()
increment a maxVal = Pledge
  { ret = ()
  , pre  = GuardedRE (PLt (ValAt a) (Lit maxVal)) universe
  , post = fromRE (Single (Atom "inc" [Num a]))
  , future = \_ -> fromPPred (PGe (ValAt a) (Lit 0)) }
\end{lstlisting}

\noindent
The \lstinline{pre} of \lstinline{increment} carries
$h[a] < M$ (pure Presburger) conjoined with the universal RE.
After composing eleven increments against a bound of~10,
\lstinline{normalizePPred} derives the contradiction
$h[a] < 10 \wedge \lnot(h[a] < 10) \equiv \mathbf{false}$,
flagging the overflow before any execution takes place.

\paragraph{Bad programs and residuals.}
\begin{center}
\begin{tabular}{lll}
\toprule
Bad program & Residual \lstinline{pre} (Presburger) & Residual \lstinline{pre} (RE) \\
\midrule
\lstinline{overflow} (11 incs, max=10) & $\mathbf{false}$ & $\univ$ \\
\lstinline{underflow} (dec at zero)    & $\mathbf{false}$ & $\univ$ \\
\lstinline{noInit} (skip init)         & $\univ$           & $\varnothing$ \\
\bottomrule
\end{tabular}
\end{center}

%% =========================================================================
\section{The WeightedRE Instance}
\label{sec:wre-instance}
%% =========================================================================

The RE and $\GRE$ instances are Boolean: a future condition is either
satisfied or violated.
The $\WRE$ instance generalises membership to a \emph{weight} drawn from
a semiring, enabling probabilistic and quantitative obligations.

\subsection{The Semiring Class}

\begin{lstlisting}
class (Eq w, Show w) => Semiring w where
    szero :: w          -- additive identity  (blocked path)
    sone  :: w          -- multiplicative identity
    sadd  :: w -> w -> w
    smul  :: w -> w -> w
\end{lstlisting}

\noindent
Setting $w = \mathtt{Bool}$ (with $\mathtt{sadd} = (\vee)$,
$\mathtt{smul} = (\wedge)$) recovers the Boolean RE instance.
Two further instances capture quantitative scenarios:

\begin{center}
\begin{tabular}{llll}
\toprule
Instance & \lstinline{szero} & \lstinline{sadd} & \lstinline{smul} \\
\midrule
\lstinline{Prob}     (probability) & $0$        & $\min(p_1+p_2,\,1)$ & $p_1 \times p_2$ \\
\lstinline{Tropical} (min-cost)    & $+\infty$  & $\min$               & $+$              \\
\bottomrule
\end{tabular}
\end{center}

\noindent
In the probability semiring, \lstinline{sadd} is bounded addition (sum of
probabilities capped at 1) and \lstinline{smul} is multiplication.
In the tropical semiring, \lstinline{sadd} is minimum (taking the
cheaper alternative) and \lstinline{smul} is addition (summing costs
along a path).

\subsection{The \texttt{WRE} Type and Operators}

\begin{lstlisting}
data WRE w
    = WBot               -- weight szero: no accepting path
    | WEps w             -- weight w: accept the empty trace
    | WSingle w Event    -- weight w: accept exactly this event
    | WSeq (WRE w) (WRE w)
    | WAdd (WRE w) (WRE w)
    | WAnd (WRE w) (WRE w)
    | WStar (WRE w)
\end{lstlisting}

\noindent
The generalised nullable function accumulates the weight of all
accepting paths through the empty trace:

\begin{lstlisting}
wNullable :: Semiring w => WRE w -> w
wNullable (WEps w)      = w
wNullable (WSeq r1 r2)  = smul (wNullable r1) (wNullable r2)
wNullable (WAdd r1 r2)  = sadd (wNullable r1) (wNullable r2)
wNullable (WAnd r1 r2)  = smul (wNullable r1) (wNullable r2)
wNullable (WStar r)     = sone
wNullable _             = szero
\end{lstlisting}

\noindent
\lstinline{wDerivative} and \lstinline{wSubtraction} follow the same
structure as their Boolean counterparts, with semiring operations
replacing Boolean ones.
The \lstinline{Composable (WRE w)} instance (enabled by
\lstinline{FlexibleInstances}) maps \lstinline{concatenation} to
\lstinline{WSeq}, \lstinline{conjunction} to \lstinline{WAnd}, and
\lstinline{subtraction} to \lstinline{wSubtraction}.

\subsection{Derived Forms}

\begin{lstlisting}
wTop     :: Semiring w => WRE w
wTop      = WStar (WSingle sone Wildcard)   -- sone-weighted anything

wFinally :: Semiring w => w -> Event -> WRE w
wFinally weight e = WSeq wTop (WSingle weight e)

wGlobally :: Semiring w => w -> Event -> WRE w
wGlobally weight e = WStar (WSingle weight e)
\end{lstlisting}

\subsection{Example: Probabilistic Memory (Prob Semiring)}

In a probabilistic setting each \lstinline{free(a)} has an associated
probability of being called.
\lstinline{malloc} carries a future condition asserting that
\lstinline{free(a)} must be called with probability $\geq p$:

\begin{lstlisting}
malloc :: Addr -> Double -> Pledge (WRE Prob) Addr
malloc a p = Pledge
  { ret = a, pre = wTop
  , post   = WSingle sone (Atom "malloc" [Num a])
  , future = \r -> wFinally (Prob p) (Atom "free" [Num r]) }
\end{lstlisting}

The residual weight of \lstinline{wNullable} at the end of a program
measures how much of the obligation has been satisfied:
a weight of \lstinline{Prob 1.0} means the obligation is fully
discharged; a weight $< 1$ names the probability shortfall.

\subsection{Example: Min-Cost Scheduling (Tropical Semiring)}

Under the tropical semiring, \lstinline{WSingle (Tropical c) e}
assigns cost $c$ to emitting event $e$.
\lstinline{wNullable} then returns the minimum total cost of
reaching the empty trace:

\begin{lstlisting}
submitJob :: Int -> Double -> Pledge (WRE Tropical) ()
submitJob jobId cost = Pledge
  { ret = ()
  , pre  = wTop
  , post = WSingle (Tropical cost) (Atom "submit" [Num jobId])
  , future = \_ ->
      wFinally (Tropical 0) (Atom "complete" [Num jobId]) }
\end{lstlisting}

Composing several \lstinline{submitJob} calls yields a future whose
\lstinline{wNullable} is the minimum total cost of completing all
submitted jobs.
A program that omits a \lstinline{complete} event for some job~$i$
retains \lstinline{wFinally (Tropical 0) (complete i)} in the
residual, and the overall weight is $+\infty$ (i.e.\ \lstinline{szero}),
flagging the missing completion.

\section{The SL Instance}
\label{sec:sl-instance}
%% =========================================================================

The \lstinline{Composable} typeclass is not tied to trace-based specifications.
We demonstrate its generality further with a fourth instance over
\emph{separation-logic heap predicates}, where future conditions describe
what heap state must hold when the computation completes.

\subsection{Structural Parallel with RE}

Table~\ref{tab:sl-re-parallel} shows the role each SL construct plays in
the \lstinline{Composable} interface.

\begin{table}[ht]
\caption{Structural parallel between the four \lstinline{Composable} instances.}
\label{tab:sl-re-parallel}
\begin{tabular}{lllll}
\toprule
Operation & $\RE$ & $\GRE$ & $\WRE_w$ & $\SL$ \\
\midrule
\lstinline{concatenation} & $r_1 \cdot r_2$ & $(p_1\wedge p_2,\,r_1\cdot r_2)$ & \lstinline{WSeq} & $P \sep Q$ \\
\lstinline{conjunction}   & $r_1 \wedge r_2$ & $(p_1\wedge p_2,\,r_1\wedge r_2)$ & \lstinline{WAnd} & $P \wedge Q$ \\
\lstinline{empty}         & $\varepsilon$ & $(\mathbf{true},\varepsilon)$ & \lstinline{WEps sone} & $\mathbf{emp}$ \\
\lstinline{universe}      & $\univ$ & $(\mathbf{true},\univ)$ & \lstinline{wTop} & $\top$ \\
\lstinline{subtraction}   & Brzozowski quotient & quotient (RE) + $\wedge$ (PPred) & \lstinline{wSubtraction} & $P \wand Q$ \\
\bottomrule
\end{tabular}
\end{table}

\noindent
The bind formula is unchanged:
$\pre(e \mathbin{>\!\!>\!\!=} f) = \pre(e) \wedge (\post(e) \wand \pre(e_2))$
and
$\fut(e \mathbin{>\!\!>\!\!=} f) = (\post(e_2) \wand \fut(e)) \wedge \fut(e_2)$.
Here $\wand$ is the magic wand (separating implication):
$P \wand Q$ holds of heap $h$ iff for every heap $h'$ disjoint from $h$
satisfying $P$, the combined heap $h \cup h'$ satisfies $Q$.

\subsection{The SL Predicate Type}

\begin{lstlisting}
data SL
    = Emp              -- empty heap         (identity for SepStar)
    | Top              -- any heap           (identity for Conj)
    | Pure PPred       -- pure Presburger constraint (heap-independent)
    | Cell Addr Val    -- singleton: address a holds value v
    | SepStar SL SL    -- P * Q  separating conjunction
    | Conj SL SL       -- P /\ Q ordinary conjunction
    | Wand SL SL       -- P -* Q magic wand (residual)
    deriving (Eq, Show)
\end{lstlisting}

\subsection{Separating vs.\ Ordinary Conjunction}

The two conjunction-like constructors have distinct semantics.
$\mathtt{SepStar}\;P\;Q$ holds of heap $h$ iff $h$ can be \emph{split}
into disjoint parts $h_1 \uplus h_2$ with $P(h_1)$ and $Q(h_2)$;
it is the standard separating conjunction of ownership.
$\mathtt{Conj}\;P\;Q$ holds of $h$ iff the \emph{same} heap satisfies
both $P$ and $Q$ simultaneously.

Without pure constraints, \lstinline{Conj} on purely spatial predicates
is either trivial or unsatisfiable:
$\mathtt{Conj}\;\mathbf{top}\;P = P$, and
$\mathtt{Conj}\;(\mathtt{Cell}\;l_1\;v_1)\;(\mathtt{Cell}\;l_2\;v_2) =
\mathbf{false}$ for distinct addresses $l_1 \neq l_2$.
The constructor becomes genuinely useful when one side is a \emph{pure
constraint}---a predicate that holds independently of the heap:
\[
  \lceil\phi\rceil \wedge (\ell \mapsto v)
  \qquad\text{(pure condition $\phi$ and spatial ownership $\ell \mapsto v$)}
\]

\subsection{Presburger Arithmetic for Pure Constraints}

Pure constraints are modelled by a small Presburger arithmetic language
over heap values.
Expressions are linear combinations of heap dereferences and literals;
predicates are comparisons and propositional connectives.

\begin{lstlisting}
data PExpr
    = Lit Int         -- integer literal
    | ValAt Addr      -- h[a]: value at address a
    | Add PExpr PExpr -- e1 + e2
    | Mul Int PExpr   -- k * e  (scalar only, keeps linearity)

data PPred
    = PTrue
    | PLt PExpr PExpr  | PLe PExpr PExpr  | PEq PExpr PExpr
    | PGt PExpr PExpr  | PGe PExpr PExpr
    | PNot PPred       | PAnd PPred PPred
\end{lstlisting}

\noindent
Derived connectives ($\mathtt{pFalse}$, $\mathtt{pOr}$) are smart
constructors built from the primitives via De Morgan laws.
\lstinline{Pure p} in an \lstinline{SL} predicate holds of any heap
for which \lstinline{evalPPred h p} is true; it is heap-independent in
the sense that it does not enforce any ownership of cells.

\paragraph{Pure syntax.}
In standard SL notation, $\lceil\phi\rceil$ (pronounced ``pure $\phi$'')
means $\phi$ holds \emph{and} the heap is empty.
The smart constructor \lstinline{pureSL} realises this:
\lstinline{pureSL PTrue = Emp} (trivially pure) and
\lstinline{pureSL p = Conj (Pure p) Emp} for non-trivial $p$.

\subsection{The \texorpdfstring{\lstinline{Composable SL}}{Composable SL} Instance}

\begin{lstlisting}
instance Composable SL where
    concatenation = SepStar
    conjunction   = Conj
    empty         = Emp
    universe      = Top

    subtraction Emp q = q           -- emp -* Q = Q
    subtraction Top _ = Emp         -- Top trivially covers any pre
    subtraction p   q = Wand p q    -- general: symbolic wand
\end{lstlisting}

\noindent
The two base cases mirror those of the RE instance:
$\varepsilon \setminus r = r$ becomes $\mathbf{emp} \wand Q = Q$
(providing no heap leaves the obligation unchanged), and
$\univ \setminus r = \varepsilon$ becomes $\top \wand Q = \mathbf{emp}$
(a $\top$ postcondition covers any precondition).
The general case records the wand symbolically for later evaluation
or normalisation.

\subsection{Normalisation}

\lstinline{normalizeSL} applies the standard SL algebraic identities:

\begin{center}
\begin{tabular}{ll}
\toprule
Law & Constructor \\
\midrule
$\mathbf{emp} \sep Q = Q$, $P \sep \mathbf{emp} = P$ & \lstinline{SepStar} \\
$\top \wedge Q = Q$, $P \wedge \top = P$              & \lstinline{Conj} \\
$P \wedge P = P$ (idempotent)                          & \lstinline{Conj} \\
$\mathbf{emp} \wand Q = Q$                            & \lstinline{Wand} \\
$P \wand \top = \top$                                  & \lstinline{Wand} \\
\bottomrule
\end{tabular}
\end{center}

\noindent
All rules apply recursively bottom-up.

%% =========================================================================
\section{Examples}
\label{sec:examples}
%% =========================================================================

We demonstrate Pledge across ten domains spanning all four instances.
Each example defines primitive operations annotated with
\lstinline{pre}, \lstinline{post}, and \lstinline{future},
composes them in the \lstinline{Effectful} monad, and inspects the
normalised annotations of the result.
A \lstinline{future} of $\univ$ (or \lstinline{wNullable = sone} for $\WRE$)
and a \lstinline{pre} of $\univ$ together certify temporal correctness.

\subsection{Memory Management}

\lstinline{malloc} returns the allocated address; its data-dependent
future condition uses the lambda parameter \lstinline{r} so the
obligation always tracks the \emph{returned} address, not a
call-site constant.
\lstinline{free} carries $\noUntil{\mathtt{free}(a)}{\mathtt{malloc}(a)}$
as its future, forbidding a second \lstinline{free(a)} unless
\lstinline{malloc(a)} resets the guard first.

\begin{lstlisting}
malloc :: Addr -> Effectful RE Addr
malloc a = Effectful
  { ret = a, pre = universe
  , post   = Single (Atom "malloc" [Num a])
  , future = \r -> finally (Atom "free" [Num r]) }

free :: Addr -> Effectful RE ()
free a = Effectful
  { ret = ()
  , pre    = previously (Atom "malloc" [Num a])
  , post   = Single (Atom "free" [Num a])
  , future = \_ -> noUntil (Atom "free" [Num a]) (Atom "malloc" [Num a]) }
\end{lstlisting}

\begin{lstlisting}
-- Good: data-dependent  -  obligation discharged on the returned address
mallocFreeByReturnedAddr n = do { addr <- malloc n; free addr }

-- Good: re-allocate the same address after freeing  -  noUntil is reset by malloc
mallocFreeReallocFree = do { a <- malloc 1; free a; a <- malloc 1; free a }

-- Bad future: free(2) obligation remains
missingFree = do { a1 <- malloc 1; free a1; _ <- malloc 2; return () }

-- Bad pre: malloc(1) precondition not met
freeWithoutMalloc = free 1

-- Bad future: double-free immediately collapses future to Bot
doubleFreeImmediate = do { addr <- malloc 1; free addr; free addr }

-- Bad future: double-free with intervening work, still collapses to Bot
doubleFreeWithWork = do
  { a1 <- malloc 1; a2 <- malloc 2; free a1; free a2; free a1 }
\end{lstlisting}

The three examples below return non-unit values, showing that future
conditions are tracked regardless of the return type.

\begin{lstlisting}
-- Good: ret = Addr; future = finally(free(1))  -  obligation visible in residual
allocReturnAddr :: Effectful RE Addr
allocReturnAddr = malloc 1

-- Bad future: ret = (Addr, Addr); future = finally(free(1)) /\ finally(free(2))
allocTwoReturnPair :: Effectful RE (Addr, Addr)
allocTwoReturnPair = do { a1 <- malloc 1; a2 <- malloc 2; return (a1, a2) }

-- Good: ret = Addr; future = noUntil(free(1), malloc(1))  -  no pending finally
allocFreeReturnAddr :: Effectful RE Addr
allocFreeReturnAddr = do { a <- malloc 1; free a; return a }
\end{lstlisting}

\subsection{Mutex / Lock Lifecycle}

\begin{lstlisting}
release :: Int -> Effectful RE ()
release m = Effectful
  { ret = ()
  , pre    = Single (Atom "acquire" [Num m])
  , post   = Single (Atom "release" [Num m])
  , future = universe }

-- Bad future: lock 1 not released
lockLeak = do { acquire 1; acquire 2; release 2 }

-- Bad pre: release without acquire
releaseWithoutAcquire = release 1
\end{lstlisting}

\subsection{Database Transactions}

\lstinline{beginTx} carries a \emph{disjunctive} future condition:

\begin{lstlisting}
beginTx = Effectful
  { ret = (), pre = universe
  , post   = Single (Atom "beginTx" [])
  , future = Or (finally (Atom "commit" []))
                (finally (Atom "rollback" [])) }
\end{lstlisting}

A program ending with neither \lstinline{commit} nor \lstinline{rollback}
retains the full disjunction as its residual future, naming both
outstanding alternatives.

\subsection{Bounded Counter (\texorpdfstring{$\GRE$}{GRE} Instance)}
\label{sec:ex-bounded}

The bounded counter (\S\ref{sec:guardedre-instance}) demonstrates that
both the Presburger and RE sides are necessary.
The RE alone would accept overflow sequences; the Presburger predicate
alone would accept arbitrary event orders.

\begin{lstlisting}
-- Good: init, two increments, one decrement, snapshot
normalUse :: Pledge GuardedRE ()
normalUse = do
  initCounter 0; increment 0 10; increment 0 10
  decrement 0;   snapshot 0

-- Bad: 11 increments against max 10
overflow :: Pledge GuardedRE ()
overflow = do
  initCounter 0
  sequence_ (replicate 11 (increment 0 10))
  snapshot 0
\end{lstlisting}

\noindent
For \lstinline{overflow}, the combined \lstinline{pre} after composing all
eleven increments normalises to
$[\mathbf{false}] \wedge \univ$: the Presburger side collapses to
\lstinline{PFalse} while the RE side remains the universal language,
pinpointing the arithmetic violation.

\subsection{Task Scheduling (\texorpdfstring{$\WRE$}{WRE} Instance)}
\label{sec:ex-sched}

The task-scheduler example shows that the tropical semiring naturally
accumulates minimum costs.
Each \lstinline{submitJob} operation carries both a submission cost and
a future condition that every submitted job must eventually complete.

\begin{lstlisting}
-- Good: submit two jobs, complete both
goodSchedule :: Pledge (WRE Tropical) ()
goodSchedule = do
  submitJob 1 2.0; submitJob 2 3.0
  completeJob 1;   completeJob 2

-- Bad: job 2 never completed
missingComplete :: Pledge (WRE Tropical) ()
missingComplete = do
  submitJob 1 2.0; submitJob 2 3.0
  completeJob 1
\end{lstlisting}

\noindent
For \lstinline{goodSchedule}, \lstinline{wNullable (evalFuture ...)}
returns \lstinline{Tropical 0}, indicating all obligations are
discharged at zero residual cost.
For \lstinline{missingComplete}, the residual future still contains
\lstinline{wFinally (Tropical 0) (complete 2)}, and the overall weight
is $+\infty$, flagging job~2 as unfinished.

The probability-semiring memory example follows analogously: a
\lstinline{malloc a p} with $p = 0.9$ leaves a residual weight of
$0.9$ if \lstinline{free a} is never called, dropping to $0$ when it is.

\subsection{Heap Memory (SL Instance)}
\label{sec:ex-heap}

The heap-memory example mirrors the RE memory example but uses heap
ownership rather than event traces.

\begin{lstlisting}
alloc :: Addr -> Val -> Effectful SL ()
alloc a v = Effectful
  { ret = (), pre = Top, post = Cell a v, future = Top }

free :: Addr -> Val -> Effectful SL ()
free a v = Effectful
  { ret = (), pre = Cell a v, post = Emp, future = Top }

writeCell :: Addr -> Val -> Val -> Effectful SL ()
writeCell a old new = Effectful
  { ret = (), pre = Cell a old, post = Cell a new, future = Top }
\end{lstlisting}

\noindent
\textbf{Good: \lstinline{alloc 0 1 >> alloc 1 2}.}
The combined \lstinline{post} is
$\mathtt{SepStar}\;(\mathtt{Cell}\;0\;1)\;(\mathtt{Cell}\;1\;2)$:
two disjoint ownerships composed by separating conjunction,
correctly reflecting that the two cells reside at distinct addresses.

\noindent
\textbf{Bad: leak (\lstinline{alloc 0 1 >> alloc 1 2 >> free 0 1}).}
After freeing only address~0, the \lstinline{post} retains
$\mathtt{Cell}\;1\;2$, naming the unreleased ownership.

\noindent
\textbf{Bad: read without ownership (\lstinline{readCell 0 42}).}
The \lstinline{pre} of the bare read is $\mathtt{Cell}\;0\;42$,
which is never discharged, flagging the missing ownership.

\subsection{Bank Account with Presburger Guards (SL Instance)}
\label{sec:ex-bank}

The bank account example demonstrates \lstinline{Pure} Presburger
constraints inside \lstinline{Conj}.

\begin{lstlisting}
withdraw :: Addr -> Val -> Val -> Effectful SL ()
withdraw a old amount = Effectful
  { ret = ()
  , pre  = Conj (Pure (PGe (ValAt a) (Lit amount))) (Cell a old)
  , post = Cell a (old - amount)
  , future = Top }

closeAccount :: Addr -> Val -> Effectful SL ()
closeAccount a bal = Effectful
  { ret = ()
  , pre  = Conj (Pure (PEq (ValAt a) (Lit 0))) (Cell a bal)
  , post = Emp, future = Top }
\end{lstlisting}

\noindent
The precondition of \lstinline{withdraw} is a \lstinline{Conj} of a pure
Presburger guard ($h[a] \geq \mathtt{amount}$) and a spatial ownership
claim ($\mathtt{Cell}\;a\;\mathtt{old}$).
Without the \lstinline{Pure} constructor, \lstinline{Conj} of two purely
spatial predicates would be either trivial or unsatisfiable (see
\S\ref{sec:sl-instance}); the combination of \lstinline{Pure} and
\lstinline{Conj} is what makes value-dependent preconditions expressible.

\noindent
\textbf{Bad: overdraft.}
After \lstinline{deposit 0 0 100}, the account holds 100.
\lstinline{withdraw 0 100 150} carries
$\pre = \mathtt{Conj}\;(\mathtt{Pure}\;(h[0] \geq 150))\;(\mathtt{Cell}\;0\;100)$.
Since $100 < 150$, the pure guard is not satisfiable, and the residual
\lstinline{pre} of the composed program retains this unsatisfiable constraint.

\subsection{Linked List (SL Instance)}
\label{sec:ex-list}

A singly-linked-list node occupies two consecutive cells:
address $a$ holds the payload value and address $a{+}1$ holds the next pointer.

\begin{lstlisting}
allocNode :: Addr -> Val -> Val -> Effectful SL ()
allocNode a val next = Effectful
  { ret = (), pre = Top
  , post = SepStar (Cell a val) (Cell (a+1) next)
  , future = Top }
\end{lstlisting}

\noindent
\textbf{Two-node list (\lstinline{allocNode 0 10 2 >> allocNode 2 20 (-1)}).}
The combined \lstinline{post} is a four-cell \lstinline{SepStar}:
\[
  (\mathtt{Cell}\;0\;10 \sep \mathtt{Cell}\;1\;2)
  \sep
  (\mathtt{Cell}\;2\;20 \sep \mathtt{Cell}\;3\;{-1})
\]
This is the canonical representation of a two-node list in separation logic:
all four cells are disjointly owned, and the structure of \lstinline{SepStar}
mirrors the structure of the list.

\section{Monad Laws}
\label{sec:monad-laws}
%% =========================================================================

Because \lstinline{future} has type \lstinline{a -> eff}, the monad laws
are stated in terms of \lstinline{evalFuture}, defined as
\lstinline{future e (ret e)}: the future condition evaluated at the
computation's own return value.
We write $\widehat{\fut}(e)$ for $\mathit{evalFuture}(e)$ for brevity.
The laws hold for the triple $(\ret, \post, \widehat{\fut})$ under the
assumption that \lstinline{Composable} forms a monoid for
\lstinline{<>} (\lstinline{empty} is the unit) and that
\lstinline{universe} is the unit for \lstinline{/\\}.
The \lstinline{pre} field satisfies the Hoare-rule property
(Equation~\ref{eq:pre-bind}) rather than strict monad-law equality;
we discuss this below.

\paragraph{Left identity} \lstinline{pure x >>= f = f x}.

$\ret$: $\ret(f\,x)$. \checkmark \quad
$\post$: $\varepsilon \mathbin{<>} \post(f\,x) = \post(f\,x)$. \checkmark

For the future, let $fe = f(\ret(\mathtt{pure}\;x)) = f\,x$.
$\mathtt{future}(\mathtt{pure}\;x) = \lambda\,\_.\ \univ$, so
$\widehat{\fut}(\mathtt{pure}\;x) = \univ$.

\begin{align*}
  \widehat{\fut}(\mathtt{pure}\;x \mathbin{>\!\!>\!\!=} f)
    &= \bigl(\post(fe) \setminus \widehat{\fut}(\mathtt{pure}\;x)\bigr)
       \wedge \widehat{\fut}(fe) \\
    &= \bigl(\post(f\,x) \setminus \univ\bigr)
       \wedge \widehat{\fut}(f\,x)
     \;=\; \varepsilon \wedge \widehat{\fut}(f\,x)
     \;=\; \widehat{\fut}(f\,x). \;\checkmark
\end{align*}

The subtraction $r \setminus \univ = \varepsilon$ holds because
$\univ \setminus r = \varepsilon$ is a base case of
\lstinline{reSubtraction}.

\paragraph{Right identity} \lstinline{e >>= pure = e}.

$\ret$: $\ret(e)$. \checkmark \quad
$\post$: $\post(e) \mathbin{<>} \varepsilon = \post(e)$. \checkmark

Let $fe = \mathtt{pure}(\ret(e))$.
Then $\post(fe) = \varepsilon$ and
\[
  \widehat{\fut}(fe)
    = \mathtt{future}(fe)\bigl(\ret(fe)\bigr)
    = (\lambda\,\_.\ \univ)\bigl(\ret(e)\bigr)
    = \univ.
\]

\begin{align*}
  \widehat{\fut}(e \mathbin{>\!\!>\!\!=} \mathtt{pure})
    &= \bigl(\varepsilon \setminus \widehat{\fut}(e)\bigr)
       \wedge \univ
     \;=\; \widehat{\fut}(e) \wedge \univ
     \;=\; \widehat{\fut}(e). \;\checkmark
\end{align*}

\paragraph{Associativity.}
For $(e \mathbin{>\!\!>\!\!=} f) \mathbin{>\!\!>\!\!=} g = e \mathbin{>\!\!>\!\!=} (\lambda\,x.\ f\,x \mathbin{>\!\!>\!\!=} g)$,
the $\ret$ and $\post$ components follow from associativity of
\lstinline{<>}.
For the future, let $r_1 = \ret(e)$, $r_2 = \ret(f\,r_1)$, $r_3 = \ret(g\,r_2)$.
Both sides reduce to
\[
  \bigl(\post(g\,r_2) \setminus
        \bigl(\post(f\,r_1) \setminus \widehat{\fut}(e)\bigr)\bigr)
  \;\wedge\; \widehat{\fut}(f\,r_1)
  \;\wedge\; \widehat{\fut}(g\,r_2)
\]
by repeated application of Equation~\eqref{eq:future-bind} and
associativity of $\wedge$.

\paragraph{Precondition.}
The \lstinline{pre} field propagates constraints via $\wedge$ (intersection).
When $\post(e)$ fully covers $\pre(e_2)$---i.e.\
$\post(e) \setminus \pre(e_2) = \varepsilon$---Equation~\eqref{eq:pre-bind}
gives $\pre(e \mathbin{>\!\!>\!\!=} f) = \pre(e) \wedge \varepsilon$.
If $\pre(e) = \univ$ (the common case for pure computations) this reduces
to $\varepsilon$, meaning the composed computation can run from an empty
start.
If $\pre(e)$ is non-nullable---e.g.\ $\pre(e) = \{a\}$---the intersection
$\{a\} \wedge \varepsilon = \varnothing$ flags a contradiction: no history
can satisfy both constraints simultaneously.
In general, the residual $\post(e) \setminus \pre(e_2)$ records
precisely which precondition obligations of the continuation remain unmet.

\section{Related Work}

\label{sec:related}

\paragraph{Pre/post-condition contracts in Haskell.}
Several lines of work encode pre/post-condition contracts in Haskell.
\emph{Liquid Haskell}~\cite{vazou2014} extends GHC with refinement types,
expressing preconditions as refinements on input types and postconditions as
refinements on output types, verified statically via an SMT solver.
Findler and Felleisen~\cite{findler2002} establish a runtime contract
discipline for higher-order functions that directly influences Haskell
contract libraries.
QuickCheck~\cite{claessen2000} supports conditional properties via the
\lstinline{==>} combinator, providing a lightweight, test-based form of
pre/post-condition checking.
Swierstra and Baanen~\cite{swierstra2019} embed Hoare triples as an indexed
monad in a dependently typed language, propagating pre/post annotations through
monadic bind analogously to our \lstinline{Effectful} monad.
Pledge complements all of these by adding a \emph{temporal}
dimension---the future condition---that none of these systems address,
and it does so without requiring type-system extensions or a dependent type
theory.

\paragraph{Future conditions.}
Song et al.\ propose future conditions as a first-class extension to
pre/post-condition contracts~\cite{song2025futurecond}, formalising the
notion that a function may leave temporal obligations for its caller to
discharge. Pledge realises this idea as a Haskell library, providing
a monadic interface and derivative-based propagation that the formal
system does not address.

\paragraph{Temporal property verification and repair.}
ProveNFix~\cite{song2024provenfix} uses temporal properties expressed as
regular expressions to guide automated program repair, verifying that
patches satisfy the specification. Pledge is complementary: rather
than repairing programs post-hoc, it carries temporal obligations as
first-class values so that violations are surfaced statically.

\paragraph{Effect systems and monads.}
The \lstinline{Effectful} monad is related to effect handlers~\cite{pretnar2015}
and graded/indexed monads~\cite{orchard2014,katsumata2014} that track
effects in types. Our contribution is orthogonal: we focus on the
\emph{temporal} dimension of effects---what must happen \emph{after}---rather
than on tracking which effects are present.

\paragraph{Session types.}
Session types~\cite{honda1993,gay2010} enforce communication protocols
at the type level, including ordering constraints. Pledge is more
lightweight: it operates at the value level, uses regular expressions
rather than types, and can be applied to any domain beyond communication.

\paragraph{Runtime monitoring.}
Runtime verification~\cite{leucker2009} checks temporal properties of
execution traces against regular-language specifications.
Pledge is a \emph{static} approach: future conditions
are computed before any execution takes place, and the embedding of
LTL\textsubscript{f} into RE (\S\ref{sec:ltl}) avoids automata
entirely.

\paragraph{Typestate.}
Typestate systems~\cite{strom1986,bierhoff2007} track resource lifecycle
in types, requiring type-system changes. Pledge is a library-level
approach requiring no language extensions beyond standard Haskell type
classes.

\paragraph{Brzozowski derivatives.}
Derivatives of regular expressions were introduced by
Brzozowski~\cite{brzozowski1964} and have found wide application in
parsing~\cite{owens2009,might2011} and model checking. Equation
\eqref{eq:deriv-not} extends the classical definition to complement;
our subtraction operator is a novel application to future-condition
propagation in a monadic setting.

\section{Discussion and Future Work}
\label{sec:discussion}
%% =========================================================================

\paragraph{Decidability.}
Equality of normalised regular expressions is decidable, so the
fixed-point computation in \lstinline{subtraction} terminates whenever
the derivative sequence is finite---which holds for the regular
languages used in our examples. Extending to context-free or
$\omega$-regular specifications remains future work.

\paragraph{Precondition monad laws.}
The \lstinline{pre} field satisfies the Hoare-rule property
rather than strict monad-law equality (Section~\ref{sec:monad-laws}).
A natural refinement is to make \lstinline{pre} a separate, non-monadic
annotation computed by a static analysis pass over the \lstinline{Effectful}
term, separating the behavioural monad from the precondition contract checker.

\paragraph{Integration with effect handlers.}
Lifting Pledge into an effect-handler framework
(\texttt{effectful} or \texttt{polysemy}) would allow temporal
specifications to be composed alongside algebraic effect rows, opening
the door to modular verification of larger programs.
A lightweight \emph{shadow} approach requires no deep integration:
the \lstinline{Effectful RE} computation is kept as a pure
specification and evaluated statically, while a separate
\lstinline{Eff es} computation carries out the real effects.
The two are written in parallel and linked only at the top level:

\begin{lstlisting}
-- Specification (pure, statically checked)
spec :: Effectful RE ()
spec = do { addr <- malloc 1; free addr }

-- Implementation (real IO via effectful)
impl :: (IOE :> es) => Eff es ()
impl = do { addr <- liftIO mallocReal; liftIO (freeReal addr) }

-- Entry point: check spec, then run impl
main :: IO ()
main = do
  assert (normalize (pre        spec) == top) "precondition violated"
  assert (normalize (evalFuture spec) == top) "future obligation unmet"
  runEff impl
\end{lstlisting}

\noindent
The specification \lstinline{spec} and the implementation
\lstinline{impl} share structure but live in separate monads.
Static checking is entirely pure; no changes to the
\texttt{effectful} stack are required.

\paragraph{Closed-world alphabet assumption.}
The \lstinline{firstWith} function handles complement soundly via
Equation~\eqref{eq:first-not}, using the union of both operands' atoms as the
working alphabet $\Sigma_0 = \mathit{atoms}(r_1)\cup\mathit{atoms}(r_2)$.
This is sound under the \emph{closed-world assumption}: every event that
could appear is mentioned somewhere in the two REs being subtracted.
An event entirely absent from both operands is never explored, so
a complement RE that accepts traces beginning with such an event
will under-approximate.
A fully open-world implementation would accept an explicit $\Sigma$
declaration, enabling complement over an unrestricted event domain
and removing the closed-world restriction.

\paragraph{Connection to indexed and graded monads.}
Because \lstinline{future :: a -> eff} indexes the obligation by the
return value rather than a fixed constant
(Section~\ref{sec:future-cond}), Pledge echoes the
\emph{indexed-} and \emph{graded-monad} literature, where types are
indexed by computational effects; here the index is a return value
instead of an effect row.

\paragraph{Solver-backed discharge of residual conditions.}
Residual annotations---a \lstinline{pre} that normalises to $\varnothing$,
or a \lstinline{future} that does not reduce to $\univ$---are currently
surfaced as symbolic expressions that the programmer must inspect manually.
A natural extension is to connect these expressions to an automatic solver:
residual RE conditions can be checked for non-emptiness by an NFA/DFA
construction or a BDD-based automaton library, while residual SL predicates
with Presburger arithmetic guards can be discharged by an SMT solver such as
Z3 or CVC5.
Integrating a solver backend would let Pledge report concrete
counterexample traces (for RE) or unsatisfiable heaps (for SL) rather than
leaving the interpretation of the residual to the user.

\paragraph{Parallel composition.}
The \lstinline{Effectful} monad is inherently sequential: bind models
one computation followed by another.
Concurrent programs require a \emph{parallel} combinator $e_1 \parallel e_2$
in which the two sub-computations interleave freely.
Under interleaving, the combined future condition must account for all
possible orderings of the two traces; in the RE instance this corresponds
to the \emph{shuffle product} $r_1 \shuffle r_2$, and the combined
postcondition is the shuffle of the individual postconditions.
The SL instance admits a natural parallel connective via the
\emph{concurrent separation logic} frame rule~\cite{o2007resources},
where disjoint heap regions are owned by parallel threads.
Extending the \lstinline{Composable} class with a \lstinline{parallel}
operation and deriving the corresponding bind-like combinator is a
natural next step towards reasoning about concurrent Haskell programs.

\paragraph{Quantitative future conditions.}
The $\WRE$ instance (\S\ref{sec:wre-instance}) generalises Boolean
membership to a semiring weight, supporting probabilistic and
min-cost future conditions within the same \lstinline{Composable}
framework.
A natural further direction is to connect $\WRE$ to probabilistic
temporal logics such as PCTL, or to quantitative Kleene algebras where
the star-semiring laws are studied axiomatically.
In the SL instance, a quantitative analogue could express amortised
resource bounds or expected heap usage; formalising the connection between
$\WRE$ and quantitative SL remains future work.

\section{Conclusion}
\label{sec:conclusion}
%% =========================================================================

We have presented Pledge, a Haskell library that extends effectful
computations with future conditions---specifications that constrain what
the remainder of a program must do.
Four design choices make the approach work.
First, the \lstinline{Composable} typeclass abstracts the specification
algebra, admitting four independent instances that all reuse the same
monadic bind formula.
Second, the $\RE$ instance integrates complement with the single algebraic
law $\partial_a(\neg r) = \neg(\partial_a r)$, enabling globally
assertions and LTL\textsubscript{f} embedding---all without automaton
construction.
Third, the $\GRE$ instance pairs each RE with a Presburger arithmetic
predicate over the heap, so that both protocol ordering \emph{and}
arithmetic bounds (overflow, underflow) are enforced in one annotation;
the predicate side is discharged by an SMT solver (Z3 via SBV) at
membership-check time, and \lstinline{normalizePPred} introduces the
canonical \lstinline{PFalse} constructor so syntactically unsatisfiable
constraints are identified immediately.
Fourth, the $\WRE$ instance replaces Boolean membership with a semiring
weight, unifying probabilistic future conditions (probability semiring)
and min-cost scheduling obligations (tropical semiring) within the same
framework.
The $\SL$ instance additionally adds Presburger arithmetic pure constraints
via \lstinline{Pure PPred} inside \lstinline{Conj}, making value-dependent
preconditions such as ``balance $\geq$ amount'' expressible as first-class
heap predicates, with magic wand as subtraction.
The resulting system is lightweight (no language extensions beyond standard
Haskell type classes), composable (a standard \lstinline{Monad} instance),
and informative across all four dimensions: a residual \lstinline{future}
names unmet trace obligations, a \lstinline{PFalse} in \lstinline{pre}
flags an arithmetic violation, a semiring weight of \lstinline{szero}
identifies an unfulfilled quantitative obligation, and a leaked
\lstinline{Cell} in a residual \lstinline{post} exposes a heap-ownership error.
